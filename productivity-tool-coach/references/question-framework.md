# 盘问问题框架

## 使用原则

盘问不是把所有可能的问题都问一遍，而是找到会改变第一版方案的关键决策。

正式选择盘问模式之前，先收集用户对痛点场景和目标工具的原始描述。不要先用选项替用户定义工具。

每个问题都要满足至少一项：

- 让目标更具体
- 让用户范围更清楚
- 让操作流程更明确
- 让第一版范围更可控
- 让实现形式或部署方式发生确定
- 让验收标准可检查

如果一个问题只是为了收集偏好、但不会影响第一版，记录为后续事项，不要优先追问。

## 初始描述和资料收集

开场先让用户回答：

- 现在遇到的具体痛点场景是什么？
- 想做什么工具？
- 当前如何处理？
- 期望得到什么结果？

如果需求涉及真实输入、现有结果或界面判断，明确邀请用户拖拽或上传：

- CSV、Excel或其他输入样例
- 图片模板、参考图片或截图
- 人工处理后的结果
- 操作流程截图
- 现有脚本、配置或报错信息

如果用户没有资料，允许回复“暂时没有”，但将相关内容记录为待确认假设。

收到附件后，先检查并总结：

1. 文件或截图中确认了什么。
2. 还缺哪些资料。
3. 哪些判断仍然只是暂时假设。

不要只回复“已收到”，也不要在没有读取资料前假装已经理解其中内容。

## 问题顺序

### 1. 问题和目标

可问：

- 你最想解决哪一件重复、耗时或容易出错的事情？
- 如果这个工具做好了，你希望哪一步明显变快？
- 这个问题多久发生一次？
- 目前最不满意的结果是什么？

### 2. 用户和场景

可问：

- 主要由谁使用？
- 是个人使用、小团队使用，还是对外提供？
- 使用者的技术熟练度如何？
- 通常在哪个设备或工作环境中使用？
- 这个工具是低频处理，还是每天高频使用？

### 3. 当前流程

可问：

- 现在通常按照什么步骤完成？
- 哪一步最耗时间？
- 哪一步最容易出错？
- 现在使用了哪些文件、工具或平台？
- 有没有一个最近发生的真实例子？

### 4. 输入和输出

可问：

- 工具需要接收什么输入？
- 输入来自文件、表格、网页、消息、数据库还是用户描述？
- 输出是文本、表格、文件、页面、提醒还是下一步操作？
- 用户需要预览、确认、修改还是直接得到结果？

### 5. 核心流程

可问：

- 用户打开工具后第一步做什么？
- 哪一步必须由用户确认？
- 哪些步骤适合自动完成？
- 失败或数据不完整时，用户需要看到什么？
- 是否需要保存历史、撤销、重复执行或导出？

### 6. 第一版范围

可问：

- 第一版必须完成哪一个核心任务？
- 哪些功能可以明确放到后续版本？
- 你更重视尽快可用，还是一次做得更完整？
- 哪个功能没有就无法验证价值？

### 7. 数据、权限和约束

可问：

- 数据是否包含敏感信息？
- 是否需要登录、权限或多人协作？
- 是否需要连接第三方服务？
- 是否必须在某个平台运行？
- 是否需要离线使用？
- 分享给别人时，对方能否安装依赖或访问部署地址？

### 8. 验收标准

可问：

- 你会用什么例子判断工具成功？
- 处理速度、准确率或格式有什么要求？
- 哪些错误必须被提示？
- 用户完成一次任务后，应该能拿到什么结果？

### 9. 是否检索现成方案

当目标和核心输入输出已经基本明确，且任务可能由现有开源项目覆盖时，询问用户是否先搜索 GitHub。这个问题不应在开场出现，也不应对用户明确要求从零制作的任务重复提出。

可问：

- 是否希望先检查 GitHub 上有没有可以直接使用或二次开发的项目？
- 你更希望先节省开发成本，还是直接按自己的方案从零设计？
- 如果发现适配度高的项目，你是否接受基于现有项目二次开发？

## 选择题生成规则

每个问题生成2到4个选项。选项应覆盖最可能的方向，但不要假装穷尽所有可能。

每次选择题都包含：

1. 问题
2. 选项
3. 默认推荐
4. 一句话推荐原因
5. 固定自由输入提醒

推荐应基于当前上下文，而不是无依据地偏好某个技术方案。

## 不知道时的处理

用户说“不知道”时：

1. 说明这个决定会影响什么。
2. 提供2到3个候选方向。
3. 推荐一个默认方案。
4. 允许用户直接接受默认方案。

不要把“不知道”变成连续追问。

## 轮次控制

### 简易模式

最多15轮。优先级：

1. 目标
2. 用户
3. 当前痛点
4. 输入
5. 输出
6. 核心流程
7. 第一版范围
8. 工具形式
9. 数据和分享约束
10. 验收标准

没有时间覆盖全部主题时，使用默认值并标记假设。

### 深入模式

没有固定短上限，但只继续解决阻塞性问题。每4到5轮可以总结一次：

```markdown
目前已经确认：
- ...

还剩下的关键问题：
- ...
```

用户说“直接出方案”时，立即结束盘问。内部保护上限建议为30轮，达到后生成带假设的方案。
