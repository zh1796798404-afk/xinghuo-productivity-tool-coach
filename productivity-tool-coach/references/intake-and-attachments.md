# 初始痛点场景和附件协作

## 目标

在选择深入盘问或简易盘问之前，先让用户用自己的话说明痛点或想改善的结果。这个阶段的目的不是开始完整盘问，而是建立低负担、可靠的需求起点。用户不必已经决定工具形式，Skill只能提出候选方向并让用户确认，不能把候选当成事实。

## 首次提示

```markdown
欢迎使用星火提效工具制作教练！

你不用一次把需求说清楚，也不用先决定做网页、脚本还是 Skill。

请先用一句话告诉我：最近哪项工作最麻烦、最重复，或者最容易出错？

如果你已经知道想做什么工具，也可以一起告诉我；如果还不知道工具形式，只描述痛点也可以。

如果你有 CSV、Excel、截图、样例结果或现有脚本，也可以直接拖拽、上传给我；暂时没有资料也没关系。
```

## 最小信息门槛

在进入模式选择前，至少需要明确：

- 一个具体痛点或工作场景。
- 一个期望改善的结果，或一个可以观察的任务产出。

如果缺少其中一项，只问一个最关键的澄清问题。不要直接开始深入盘问，也不要自行指定工具形式。工具形式可以暂时记录为候选。

## 附件触发条件

需要真实资料时，明确说明资料类型和用途：

```markdown
为了准确判断第一版的输入、输出和处理流程，我还需要最小资料：

- 一份脱敏的CSV样例，用来确认字段结构。
- 一张参考图片或模板截图，用来确认图片处理方式。
- 一份期望输出，用来确认最终结果。

请直接拖拽或上传。优先提供一份小样本，不需要完整历史数据。没有这些资料时，请回复“暂时没有”，我会按当前描述继续，并把相关内容标记为待确认假设。
```

典型映射：

| 场景 | 建议用户提供 |
| --- | --- |
| CSV或Excel批处理 | 脱敏样例、字段说明、期望输出 |
| 图片生成或批量刷图 | 模板图、参考图、字段示例、期望结果 |
| 复刻现有操作 | 操作截图、现有文件、报错信息 |
| 数据分析工具 | 样例数据、字段定义、期望报表 |
| 网页或界面工具 | 现有页面截图、草图、参考页面 |
| 文件转换工具 | 输入文件、输出样例、失败案例 |

## 收到附件后的动作

附件上传后：

1. 检查文件是否可读取、格式是否正确、是否包含敏感信息。
2. 总结从文件或截图中确认的事实。
3. 指出还缺少的资料或需要用户确认的地方。
4. 再让用户选择深入或简易盘问模式。

不要只回复“已收到”。不要在没有读取附件时声称已经理解文件内容。

## 没有附件时的动作

用户说“暂时没有”或无法上传时：

- 不要阻塞整个流程。
- 使用用户文字描述继续。
- 将真实输入格式、异常情况和期望结果记录为假设。
- 在最终制作方案中明确列出需要用户后续补充的资料。

## 安全和隐私

- 提醒用户先删除姓名、电话、邮箱、客户编号、内部链接、密钥和其他敏感信息。
- 不要求用户上传与当前决策无关的完整数据集。
- 优先请求最小可用样例。
- 如果文件中可能包含凭证或密钥，先停止读取并提醒用户移除。
