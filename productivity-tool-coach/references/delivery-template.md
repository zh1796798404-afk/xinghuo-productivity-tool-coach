# 确认门、验收核对与交付模板

## 正式方案 = 定稿后的草稿

v1.4 起不再有独立的方案模板：`提效工具方案.md` 按 [draft-plan.md](draft-plan.md) 完成定稿（所有 `[待确认]` 消除、未答项转假设、状态行改为"待确认制作"）后，它就是正式制作方案。

## 确认门展示（聊天内只给摘要）

不在聊天内重贴方案全文，只展示三样东西——关键决定、变化、假设：

```markdown
🎉 **方案草稿已定稿**（完整内容见 `提效工具方案.md`）

**关键决定**

1. 🎯 做什么：…
2. 🛠 工具形式：…
3. 📥→📤 输入 → 输出：…
4. 🧩 第一版只做：…；暂不做：…
5. ✅ 验收标准：共 N 条（见文件第 9 节）

**自上次小结以来的变化**

- …

**仍在使用的假设（M 条）**

- …

---

没有问题的话，请回复：**"确认方案，开始制作"**

需要修改？直接告诉我调整哪部分。
```

用户没有明确确认时，不开始创建或修改工具。用户提出修改时，只修改受影响的部分并重新展示关键差异，不重新梳理全部内容。

## 验收标准句式（写入草稿第 9 节时即约束）

```text
当 [条件/动作] 时，工具应 [可观察的结果]。

例：当上传 50 行的订单 CSV 时，工具应生成 50 张文件名含订单号的图片；
    字段缺失的行不中断处理，列入失败清单。
```

每条标准必须配一个具体例子，优先取自用户上传的真实样例。

## 验收核对规则

- 逐条核对草稿第 9 节的每条标准，结果只有三种：✅ 通过 / ⚠️ 部分通过 / ❌ 未通过。
- 证据必须可检查：实测输出的位置、运行命令、截图或数字，不写"应该没问题"。
- 未通过的标准：要么修复后重测，要么经用户知情同意降级为"已知限制"写入交付说明。不得静默跳过。
- 核对完成后更新草稿状态行为"已交付"，并在版本记录追加一行。

## 分享前检查

交付前确认：

- 其他人是否知道从哪里开始？
- 是否知道需要什么依赖或账号？
- 是否知道输入格式？
- 是否知道成功结果是什么？
- 是否知道工具的限制？
- 是否能在不依赖当前对话的情况下使用？
