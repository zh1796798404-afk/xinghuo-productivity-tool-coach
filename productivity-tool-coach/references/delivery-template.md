# 确认门、验收核对与交付模板

## 正式方案 = 定稿后的草稿

v1.4 起不再有独立的方案模板：`提效工具方案.md` 按 [draft-plan.md](draft-plan.md) 完成定稿（所有 `[待确认]` 消除、未答项转假设、状态行改为"待确认制作"）后，它就是正式制作方案。

## 确认门展示（聊天内只给摘要）

不在聊天内重贴方案全文，只展示三样东西——关键决定、变化、假设：

```markdown

4. 🧩 第一版只做：…；暂不做：…
5. ✅ 验收标准：共 N 条（见文件第 9 节）

**自上次小结以来的变化**

- …

**仍在使用的假设（M 条）**

- …

---

没有问题的话，请回复：**"确认方案，开始制作"**

需要修改？直接告诉我调整哪部分。
```

用户没有明确确认时，不开始创建或修改工具。用户提出修改时，只修改受影响的部分并重新展示关键差异，不重新梳理全部内容。

## 验收标准句式（写入草稿第 9 节时即约束）

```text
当 [条件/动作] 时，工具应 [可观察的结果]。

例：当上传 50 行的订单 CSV 时，工具应生成 50 张文件名含订单号的图片；
    字段缺失的行不中断处理，列入失败清单。
```

每条标准必须配一个具体例子，优先取自用户上传的真实样例。

## 手册写作规则（把用户当成完全的小白）

- 分步格式固定为"第一步 / 第二步 / 第三步…"，每步只做**一个动作**，以"打开、点击、拖入、粘贴、按"等动词开头。
- 步骤中出现的文件名、按钮名、菜单名一律用界面原文并**加粗**，让用户能在屏幕上对着找。
- 不出现技术术语：终端、依赖、环境变量、路径、端口这类词不允许直接出现；确实绕不开命令时，给一整行可复制的内容，并用一句话写明"复制后粘贴到哪里、然后按什么键"。
- 从"打开"写到"看到第一个成功结果"，中间一步都不能跳；"常见问题"里的解决方法同样用分步格式写。
- 自检标准：一位从没做过这件事的同事，不问任何人，能照着手册完成第一次使用。做不到就重写，不得交付。

## 验收核对规则

- 逐条核对草稿第 9 节的每条标准，结果只有三种：✅ 通过 / ⚠️ 部分通过 / ❌ 未通过。
- 证据必须可检查：实测输出的位置、运行命令、截图或数字，不写"应该没问题"。
- 未通过的标准：要么修复后重测，要么经用户知情同意降级为"已知限制"写入交付说明。不得静默跳过。
- 核对完成后更新草稿状态行为"已交付"，并在版本记录追加一行。

## 试用与微调闭环（交付后必经，不得以"已完成"结束）

交付说明发出后，紧接以下引导：

```markdown
🧪 **最后一步：亲手试一遍**——工具是给你用的，你说好才算好。

- **A.** 我现在就照上面的手册自己走一遍　⭐ 推荐
- **B.** 你先自动再测一遍给我看结果，然后我再自己试

💡 **推荐 A**：制作时我已经用你的样例跑通过一轮（见上面的验收核对表），你亲手走一遍，最能发现"不顺手"的地方。

*如果以上选项都不符合，可以直接输入你自己的想法。*
```

用户选 A（手动试用）：

```markdown
试完了吗？**哪里不顺手、哪里不对，直接告诉我**——按钮位置、字段顺序、速度、结果格式，多小的点都值得说，我来改，**改到你满意为止**。

都顺手的话，回复"**满意**"，我就收尾。
```

用户选 B（先自动）：重跑全部验收标准并补几个边界样例，用一行式报告结果，然后仍然引导手动试用：

```markdown
🧪 **自动测试完成**：[一行式结果，例：23 张样例重跑全流程 ✅ · 金额与人工核对一致 ✅ · 模糊件正确进入失败清单 ✅]

现在轮到你了——**照手册亲手走一遍**（毕竟每天用它的是你），哪里不顺手直接说，我改到你满意为止。
```

反馈处理规则：

- 每收到一条反馈：修改 → 重跑受影响的验收项 → 一行式反馈告知（`📝 已调整：… · 重跑验收第 N 条 ✅`）→ 请用户复试对应的手册步骤。
- 自动测试不能替代用户亲手试用；用户没上手之前不进入收尾。
- 循环直到用户明确表示满意（"满意""没问题""可以了"等），不主动催促结束。

用户表示满意后：先按 [platform-sync.md](platform-sync.md) 询问是否上传星火平台并处理上传与登记，**然后**发收尾消息（如有上传，收尾里带上传结果和下载直链）。

收尾模板：

```markdown
🎉 **收工！** 草稿已标记为「已交付 · 试用通过」。
以后想加功能、改问题，随时再次调用我——我认得这个工具，不会从头问起。
```

## 分享前检查

交付前确认：

- 其他人是否知道从哪里开始？
- 是否知道需要什么依赖或账号？
- 是否知道输入格式？
- 是否知道成功结果是什么？
- 是否知道工具的限制？
- 是否能在不依赖当前对话的情况下使用？
