# 星火提效工具制作教练

一个帮助用户把业务痛点逐步梳理成可制作、可使用、可验证、可分享工具的 Agent Skill。

## 核心体验

这个 Skill 不要求用户一开始写完整需求，也不要求先决定使用网页、脚本还是 Skill。用户只需要先说出一项最麻烦、最重复或最容易出错的工作，教练会用低负担的单问题对话逐步补齐信息。

v1.4 的核心机制是**方案草稿先行**：教练在对话早期就生成一份落盘的方案草稿（`提效工具方案.md`），之后每个问题都用来填草稿上的一个 `[待确认]`。用户每答一题就看到草稿被填掉一格，而不是在问卷式提问的终点才第一次见到方案。

当前流程是：

```text
清晰描述想做的工具（只说痛点也行）
→ 描述完整：草稿直出（草稿即复述）；描述简短：复述 + 邀请讲"最近一次"的真实经过
→ 覆盖度记分板驱动的单问题澄清：每答一题当场写回草稿
→ 必要时检索 GitHub 现成工具 / 提供2到3个视觉辅助方向
→ 草稿定稿，展示关键决定摘要，等待明确确认
→ 制作、逐条验收核对、分步小白手册
→ 试用与微调闭环：手动/自动测试 → 反馈微调 → 用户说"满意"
→ 再次调用时走迭代短流程
```

## 主要能力

- 引导式开场：先引导把模型与推理档位调到最高（提高制作一次成功率），再请用户清晰描述想做的工具并配示范级例子，明确告知"说得越清楚，后面问得越少"；只说痛点也能开始。
- 草稿直出：初始描述完整时不再单独复述，直接生成方案草稿——草稿即复述，用户对着草稿纠错。
- 真实事例锚定：描述简短时优先问"上次是怎么做的"，从一个真实故事里提取输入、步骤、输出和耗时，代替多轮抽象提问。
- 方案草稿先行：草稿从第2轮起就落盘存在，全程可见、可手工修改；用户改动是最高优先事实。
- 覆盖度记分板：九个维度按"清晰/部分/缺失"跟踪，按"影响度×不确定性"挑最值得问的问题；进度呈现为"9项里7项已清晰"。
- 动态问题数：硬上限5问，初始描述越完整问得越少，0问直接出方案也正常；出现多人、权限、外部对接等信号时可进入深挖（上限10问）。
- 动态选择题：通常2到3个基于当前场景生成的选项，含默认推荐、推荐原因和自由输入出口；每个问题首行标注它填草稿的哪一栏。
- 低负担回答：支持"按推荐继续""我不确定""暂时跳过""先给我初版方案"。
- 疲劳收尾：用户连续表示不确定或希望加快时，自动定稿草案，不继续堆问题。
- 附件协作：顺着真实事例邀请上传CSV、Excel、截图、样例结果或现有脚本，优先请求最小脱敏资料。
- GitHub复用评估：检索2到5个候选项目，评估适配度、维护状态、许可证和二次开发难度，结论写回草稿。
- Visual Companion：在看实际方案比读文字更容易决策时，提供2到3个视觉或流程方向，不局限于网页。
- 确认门：用户明确确认制作方案后，才创建或修改工具。
- 验收核对：验收标准统一为"当…时，工具应…"句式并配具体例子；交付说明以逐条"通过/未通过 + 证据"的核对表开头。
- 简单高效优先：同等满足需求时优先图形化界面（不强制），能双击就不敲命令，能零依赖就不装环境。
- 小白交付：手册固定"第一步：打开××、第二步：点击××"的分步格式，零术语；标准是没接触过的人不问任何人也能完成第一次使用。
- 试用与微调闭环：交付后提供"手动试用 / 先自动测试再手动"的选择（自动不替代上手），收集反馈持续微调，直到用户明确表示满意。
- 平台协同：制作过程元数据静默回传星火平台制作记录（build_session），用户满意后可一键上传工具回平台并登记工具表；需本地配置 `~/.spark-coach/config.json`，未配置时自动禁用、流程不变。
- 一体化双模式：制作模式从痛点到工具；上传模式服务存量工具——开场说"上传工具"或拖入工具目录即触发，自动解析生成全部上架字段、一屏确认后传回平台（来源渠道=存量工具插件上传）。
- 迭代短流程：再次调用且已有工具时，直接确认改动点并修改，不重新走完整梳理。

每道选择题都保留自由输入出口：

```text
如果以上选项都不符合，可以直接输入你自己的想法。
```

## 安装

### Codex

将 `productivity-tool-coach` 文件夹复制到：

```text
~/.agents/skills/productivity-tool-coach
```

或：

```text
~/.codex/skills/productivity-tool-coach
```

新建任务后显式调用：

```text
$productivity-tool-coach
```

### Claude Code

将 `productivity-tool-coach` 文件夹复制到：

```text
~/.claude/skills/productivity-tool-coach
```

调用：

```text
/productivity-tool-coach
```

### 从 GitHub 下载

下载仓库中的 `productivity-tool-coach` 文件夹，并按照上面的平台说明复制到对应目录。安装后建议重新打开客户端或新建任务，确保读取到最新文件。

## 目录结构

```text
productivity-tool-coach/
├── SKILL.md
├── agents/
│   └── openai.yaml
└── references/
    ├── intake-and-attachments.md
    ├── low-burden-conversation.md
    ├── draft-plan.md
    ├── question-framework.md
    ├── visual-companion.md
    ├── github-reuse.md
    ├── delivery-template.md
    ├── platform-sync.md
    └── upload-mode.md
```

`SKILL.md` 保存工作契约、流程路由和确认门。`references/` 保存开场与附件协作、低负担对话、方案草稿规则、记分板与问题框架、视觉辅助、GitHub复用评估以及确认门与交付模板。`agents/openai.yaml` 是 Codex 界面配置，Claude Code 可以忽略。

## 当前版本

**v1.4.0**

v1.3 降低了"开始"的负担，v1.4 降低"中途"的负担——从问卷式收集，变成对着一份看得见、不断长大的草稿做填空。本版本吸收了 GitHub Spec Kit（草案先行、覆盖度扫描、答案写回）、AWS Kiro（可测试验收标准）和 Mom Test（真实事例访谈）中的成熟方法：

- 新增方案草稿先行：草稿早期落盘，每个问题对应草稿上的一个空格。
- 新增覆盖度记分板：替代轮数控制，进度可感知，提问优先级有明确算法。
- 新增真实事例锚定：邀请用户讲"最近一次"的实际经过，减少抽象提问（描述已完整时自动跳过）。
- 新增验收核对：验收标准可测试化，交付时逐条核对并给出证据。
- 取消开场模式选择题：默认标准路线，按需深挖，减少一个用户答不好的决定。
- 新增迭代短流程：改已有工具时不再重新走完整梳理。
- 开场升级：引导清晰描述想做的工具（配示范级例子），描述完整时草稿直出（草稿即复述）。
- 新增试用与微调闭环：交付后手动/自动测试可选，反馈持续微调，直到用户明确满意。
- 新增平台协同：制作记录（build_session）静默回传 + 工具一键上传回流，对接星火平台数据表。
- 新增上传模式：存量工具自动解析、一屏确认、上传回流，与制作模式构成一体化双模式（对齐平台 PRD 4.2）。
- 用户可见文案中"盘问"统一改为"梳理"。

## 兼容性

Codex 和 Claude Code 共用 `SKILL.md` 与 `references/`。不同客户端的安装目录和 Skill 发现策略可能不同，建议使用显式调用（`SKILL.md` 已配置 `disable-model-invocation: true`，`agents/openai.yaml` 已关闭隐式调用）。
